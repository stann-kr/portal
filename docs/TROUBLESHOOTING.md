## 2026-03-27

### 인증 provider 병합으로 로그인 전면 불가

#### 증상

- 어드민·학생 계정 모두 로그인 시 자격 증명이 올바르지 않다는 응답을 받는다.
- 비밀번호 해시 비교를 수동으로 테스트하면 정상 통과한다.
- 검증 함수 안의 오류 로그가 전혀 출력되지 않는다. 함수 자체가 호출되지 않는다는 신호다.

#### 원인

- NextAuth v5는 Edge 호환 설정 파일과 런타임 설정 파일의 `providers` 배열을 병합한다.
- 설정 파일 쪽에 검증 함수 없는 빈 provider가 먼저 등록돼 있으면 그쪽이 우선 적용되어 항상 인증 실패를 반환한다.

#### 해결

- Edge 호환 설정 파일의 `providers`는 빈 배열로 두고, 실제 provider는 런타임 설정 파일에서만 등록한다.

#### 검증

- npm run build가 성공한다.
- /login과 보호 route의 HTTP 응답·redirect가 의도한 경로를 가리킨다.

#### 재발 방지

- 설정을 두 파일로 분리하는 패턴에서는 provider 등록 지점을 한 곳으로 고정한다.

### 서버 액션 파일에서 동기 함수 재노출 시 컴파일 실패

#### 증상

- 빌드 로그에 서버 액션 파일에서는 async 함수만 export할 수 있다는 오류가 출력된다.

#### 원인

- 파일 상단에 서버 액션 지시어가 있으면 컴파일러가 그 파일의 모든 export를 서버 액션으로 처리한다. 동기 헬퍼를 재노출하면 규칙에 위배된다.
- 지시어를 함수 내부로 옮기면 이번엔 클라이언트 컴포넌트에서 인라인 서버 액션을 정의할 수 없다는 오류로 바뀐다.

#### 해결

- 클라이언트와 서버가 함께 쓰는 타입·헬퍼는 지시어 없는 별도 유틸 파일로 분리하고, 임포트 경로를 그쪽으로 옮긴다.

#### 검증

- npx tsc --noEmit과 npm run build가 성공한다.

### 리치텍스트 에디터 SSR 하이드레이션 불일치

#### 증상

- 에디터가 포함된 페이지 로드 시 서버 렌더링이 감지됐다는 오류와 함께 하이드레이션 불일치가 발생한다.

#### 원인

- 에디터 훅이 기본적으로 서버에서도 즉시 렌더링을 시도해 서버와 클라이언트의 초기 렌더 결과가 달라진다.

#### 해결

- 에디터 훅 옵션에서 즉시 렌더링을 비활성화한다. 해당 에디터를 쓰는 모든 화면에 동일하게 적용한다.

#### 검증

- npm run build가 성공하고 에디터 route의 server render 로그에 hydration 오류가 없다.

## 2026-03-25

### 정적 생성 단계에서 환경 변수 참조 오류

#### 증상

- 빌드의 정적 페이지 생성 단계에서 `undefined`의 속성을 읽을 수 없다는 오류가 발생한다.

#### 원인

- 클라이언트 컴포넌트 페이지가 서버 액션 모듈을 직접 임포트하면 서버 액션 청크 참조가 페이로드에 포함되는데, 청크 맵에 등록되지 않아 참조가 깨진다.
- 컨테이너에 개발 환경 변수가 고정돼 있어 빌드 시 개발 런타임이 사용되면서 검증이 더 엄격하게 걸린다.

#### 해결

- 서버 컴포넌트 래퍼와 클라이언트 컴포넌트를 분리하는 구조로 전환한다.
- 인증 기반 앱이라 정적 생성이 불필요하므로 전체를 동적 렌더링으로 전환한다.

#### 검증

- 환경 변수 실값을 출력하지 않은 상태에서 npm run build가 성공한다.

#### 재발 방지

- 클라이언트 컴포넌트 페이지에서 서버 액션 모듈을 직접 임포트하지 않는다.

## 2026-03-24

### 배포 시 Node.js 내장 모듈 해석 실패

#### 증상

- 빌드는 끝났는데 업로드 단계에서 파일 시스템·경로·암호화·비동기 컨텍스트 등 내장 모듈을 찾지 못해 배포가 실패한다.

#### 원인

- Workers 런타임의 호환성 날짜가 낮으면 최신 Node.js 호환 동작이 활성화되지 않는다.

#### 해결

- 호환성 날짜를 내장 모듈 자동 처리가 포함된 버전 이상으로 올린다.

#### 검증

- npm run build:worker가 성공한다.

### 빌드 환경 의존성 충돌과 lockfile 불일치

#### 증상

- CI 빌드의 클린 설치 단계에서 peer dependency 충돌 또는 lockfile 불일치로 설치가 중단된다.

#### 원인

- 클린 설치는 일반 설치보다 엄격하게 무결성을 검사한다. 매니페스트만 수정하고 lockfile을 갱신하지 않으면 즉시 실패한다.
- 배포 어댑터가 요구하는 프레임워크 버전 범위와 프로젝트 버전이 어긋나 있었다.

#### 해결

- 컨테이너 안에서 설치를 실행해 lockfile을 동기화한 뒤 커밋한다.
- 필요하면 peer dependency 검사 완화 설정을 두되, 프레임워크 버전을 요구 범위에 맞춰 올리는 쪽을 우선한다.

#### 검증

- lockfile 기준 설치 후 npm run build와 npm run build:worker가 성공한다.

### 배포 어댑터가 모든 라우트에 엣지 런타임을 강제

#### 증상

- 빌드 시 Node.js 런타임을 쓰는 모든 API와 SSR 페이지에 엣지 런타임 선언이 없다는 오류가 난다.

#### 원인

- 당시 어댑터는 모든 서버 로직을 엣지 함수로만 변환할 수 있어, Node.js 의존성이 있는 앱 전체를 수동 전환해야 했다.

#### 해결

- 엣지 강제가 없는 어댑터로 전환하고 진입점과 자산 경로를 새 어댑터 기준으로 바꾼다. Node.js 호환 플래그를 활성화하면 개별 선언 없이 배포된다.

#### 검증

- npm run build와 npm run build:worker가 모두 성공한다.

### 프로덕션 빌드에서 페이지 라우터 충돌 오류

#### 증상

- 프로덕션 빌드 단계에서 문서 컴포넌트를 페이지 라우터 밖에서 임포트하면 안 된다는 오류와 함께 오류 페이지 렌더링이 실패한다.

#### 원인

- 컨테이너에 개발 환경 변수가 전역 고정돼 있어 프로덕션 빌드에서도 개발용 플랫폼 설정 매크로가 실행됐다. 개발용 목업이 프로덕션 컴파일에 섞이면서 내부 라우터가 깨졌다.

#### 해결

- 빌드 명령 실행 시 프로덕션 환경 변수를 명시적으로 오버라이드한다.

#### 검증

- npm run build가 중복 route 또는 pages 충돌 없이 성공한다.

### 검색 파라미터 훅으로 정적 렌더 실패

#### 증상

- 여러 페이지 빌드에서 검색 파라미터 훅을 경계 컴포넌트로 감싸야 한다는 렌더링 실패가 발생한다.

#### 원인

- 클라이언트 컴포넌트 최상단에서 검색 파라미터 훅을 직접 쓰면 빌드 단계에서 쿼리를 알 수 없어 정적 렌더 최적화가 중단된다.

#### 해결

- 쿼리 의존 로직을 내부 컴포넌트로 분리하고 부모에서 경계 컴포넌트로 감싼다.

#### 검증

- npm run build가 prerender 오류 없이 성공한다.

## 2026-03-10

### 개발 환경에서 데이터베이스 바인딩 미주입

#### 증상

- 로그인 시도 시 콜백 오류가 발생하고 로그에 데이터베이스 바인딩을 찾을 수 없다고 출력된다.

#### 원인

- 당시 어댑터의 개발 플랫폼 설정은 특정 전역 객체 존재 여부로 실행을 결정해서 일반 Node.js 환경에서는 설정 자체가 건너뛰어졌다.
- 설정이 실행되더라도 서버 액션 컨텍스트까지는 바인딩 패치가 전파되지 않았다.

#### 해결

- 개발 환경 전용 폴백을 두어, 바인딩이 없으면 로컬 에뮬레이터가 저장한 SQLite 파일에 직접 접근하도록 한다.

#### 검증

- 개발 서버에서 인증 후 데이터 조회 route가 DB binding 오류 없이 응답한다.

### 컨테이너 베이스 이미지와 런타임 바이너리 비호환

#### 증상

- 로컬 실행 시 런타임 바이너리 로드에 실패하거나 심볼을 찾을 수 없다는 오류가 난다.

#### 원인

- Alpine 계열 이미지는 musl libc를 쓰는데 Workers 런타임 엔진은 glibc 기반이다.

#### 해결

- 베이스 이미지를 Debian 계열로 교체해 glibc 환경을 확보한다.

#### 검증

- docker compose run --rm web node --version과 docker compose run --rm web npm run build가 성공한다.

### 컨테이너에서 CLI 실행 경로를 찾지 못함

#### 증상

- 개발 서버나 CLI 호출 시 명령을 찾을 수 없다는 오류가 발생한다.

#### 원인

- 컨테이너 `PATH`에 로컬 바이너리 경로가 포함되지 않았다.
- 익명 볼륨 설정 때문에 의존성 디렉터리가 기동할 때마다 덮어써지거나 유실됐다.

#### 해결

- 스크립트에서 바이너리 호출 앞에 실행기를 명시해 경로를 강제한다.
- 볼륨을 네임드 볼륨으로 전환해 재시작 후에도 의존성이 유지되도록 한다.

#### 검증

- docker compose run --rm web npm run build가 로컬 설치 CLI를 사용해 성공한다.

### 컨테이너 기동 시 의존성 설치가 건너뛰어짐

#### 증상

- 컨테이너를 띄우면 의존성 디렉터리가 없거나 패키지를 찾을 수 없다는 오류가 반복된다.

#### 원인

- compose 파일의 `command`가 이미지의 기본 실행 명령을 완전히 덮어써서 설치 단계가 실행되지 않았다.

#### 해결

- compose 파일에서 `command` 키를 제거하고 이미지의 기본 실행 명령이 그대로 동작하도록 되돌린다.

#### 검증

- 새 volume 기준 컨테이너에서 의존성 설치 후 npm run lint가 성공한다.

### 환경 변수 파일이 컨테이너에 전달되지 않음

#### 증상

- 로컬 환경 변수 파일에 인증 비밀 키가 정의돼 있는데도 컨테이너 안에서 인식되지 않아 관련 오류가 반복된다.

#### 원인

- compose 파일에 환경 변수 파일 설정이 없어 값이 컨테이너로 주입되지 않았다.

#### 해결

- 해당 서비스에 환경 변수 파일 설정을 추가한다.

#### 검증

- secret 실값을 출력하지 않고 필수 변수의 존재 여부와 애플리케이션 기동을 확인한다.

### 파일명 규약 불일치로 인증 미들웨어 미동작

#### 증상

- 로그인 없이 보호된 경로에 직접 접근할 수 있다. 인증 리다이렉트가 전혀 걸리지 않는다.

#### 원인

- App Router는 정해진 파일명만 미들웨어로 인식하는데 다른 이름으로 작성돼 있어 로드 자체가 되지 않았다.

#### 해결

- 규약에 맞는 파일명으로 옮긴다.

#### 검증

- 비로그인 보호 route 요청이 /login으로 redirect되는지 HTTP 응답으로 확인한다.

#### 재발 방지

- 보호 경로에 직접 접근해 리다이렉트가 걸리는지 확인한다.

### 로컬 스크립트에서 데이터베이스 어댑터 연결 실패

#### 증상

- 로컬에서 시드 스크립트를 실행하면 대상 객체가 정의되지 않았다는 오류가 발생한다.

#### 원인

- 플랫폼 의존성이 있는 어댑터는 일반 Node.js 런타임에서 바인딩 객체를 인식하지 못한다.

#### 해결

- 개발 환경과 명시적 opt-in을 확인한 뒤 로컬 에뮬레이터의 SQLite 파일에만 접근한다.
- 관리자 정보는 `.env.local`의 개발 전용 변수에서 읽고, prepared statement로 직접 저장한다. 비밀번호·해시를 명령행이나 SQL 출력으로 전달하지 않는다.

#### 검증

- 단위 회귀 테스트에서 개발 환경 guard, 명령행 인자 거부, password hash, prepared statement 입력 binding을 확인한다.

### 포트 점유 충돌

#### 증상

- 개발 스크립트 실행 시 포트 바인딩에 실패한다.

#### 원인

- 이전 프로세스가 정상 종료되지 않았거나 다른 컨테이너가 같은 포트를 점유하고 있다.

#### 해결

- 컨테이너와 네트워크 리소스를 완전히 정리한 뒤 다시 기동한다.

#### 검증
