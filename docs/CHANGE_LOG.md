# 변경 이력

공개 가능한 결과 중심 변경 요약이다. 날짜 아래에 같은 날의 변경을 모으고 최신 항목을 위에 둔다.

## 2026-08-06

### 변경 요약

- 개인 노트에 version 기반 동시 편집 감지와 full-snapshot 불변 revision 이력을 추가했다. 같은 저장 요청은 operation ledger로 정확히 재전송하고, 과거 요청의 결과 revision과 현재 head revision을 구분해 최신 내용을 되감지 않는다.
- 노트 삭제를 30일 휴지통으로 바꾸고 목록 분리, 상세 읽기 전용 상태, 복원, 변경 이력 조회·과거 버전 복원과 만료 뒤 관리자 영구 삭제를 제공한다. 영구 삭제 뒤에는 최소 tombstone이 같은 ID의 부활을 막는다.
- Server Action 요청 envelope 여유를 포함해 sanitize된 노트 본문 800 KiB·제목 200자·사용자별 내용 저장 100 MiB 정책을 적용했다. 충돌 시 자동 병합하지 않고 내 초안을 유지한 채 서버 최신본을 펼쳐 확인·복사하고 어느 쪽을 사용할지 선택한다.
- 새 `0008` migration은 기존 노트를 version 1 `BASELINE`으로 이관하고 profile 삭제를 `RESTRICT`한다. migration doctor가 CHECK·trigger, 불변/부활 방지 부정 probe, `0007` fixture upgrade와 inbound foreign key 차단까지 검사한다.

## 2026-08-05

### 변경 요약

- 입력이 계속돼 지연 저장이 밀려도 첫 변경 뒤 최대 5초에는 최신 초안을 저장한다. 노트·게시물 편집 초안은 서버 기준 대형 본문을 다시 복제하지 않고 짧은 지문만 보존해 512KiB 본문도 로컬 payload에 한 번만 포함한다. 기준 metadata가 없거나 손상된 편집 초안은 서버본과 다를 때 안전한 stale 상태로 열고, 노트 자체 저장의 정규화 결과를 외부 변경으로 오인하지 않는다. 저장 성공은 compact·기준 metadata 없는 표현·현재와 실제 복원한 구버전 표현을 제출 완료로 기록해 업데이트 전 탭의 ghost 복원을 막는다.
- 저장소 읽기·쓰기·삭제가 모두 차단된 순간 제출돼도 같은 페이지 세션의 cutoff가 이전 canonical·복구본 재등장을 막고, 시스템 시계가 뒤로 보정돼도 이미 관측한 같은 내용의 causal 저장 시각보다 cutoff를 낮추지 않는다. 다른 문서를 보고 있더라도 저장소 회복 뒤 이탈 경계에서 durable tombstone과 복구본 승격을 완료한다. 열지 않은 문서의 30일 초과 불변 복구본은 브라우저 유휴 시간에 작은 단위로 안전하게 정리하고, 큰 복구본과 marker는 문서별 정리 또는 저장공간 재시도 경계에서 처리한다. 복구본 목록·만료 marker·여러 제출 표현 정리는 한 번 해석한 대형 원문과 namespace 상태를 재사용하고 raw CAS로 마무리한다.
- 첨부 업로드 중에는 제목·분류·본문·첨부 변경과 저장 단축키를 함께 잠근다. 새 게시물·Q&A 질문·답변의 실제 form 조합 테스트로 단축키가 최신 본문만 로컬 저장하고 공개 action을 호출하지 않는 계약을 보호한다.
- 복구본 목록에 전체 저장 시각, 안전하게 잘라낸 제목·본문 미리보기와 현재 화면본 표시를 추가하고, 삭제는 취소를 우선하는 2단계 확인을 거치게 했다. 더 최신 앱이 만든 로컬 초안은 원문을 보존한 채 구버전 화면의 제출을 차단하며, 그 뒤 저장소 읽기·쓰기가 실패해도 잠금과 현재 화면 안전본을 유지한다.
- 새 게시물·Q&A 질문·답변에서 `Cmd/Ctrl+S`는 게시·등록하지 않고 현재 입력을 로컬 초안으로만 즉시 저장한다. 실제 공개 동작은 명시적인 버튼으로 분리하고, 노트·기존 문서 편집의 서버 저장 단축키와 안내 문구를 구분했다.
- 제목이나 본문 없이 날짜만 바꾸거나 비운 노트와 채널·분류·고정 여부만 바꾼 게시물도 초안으로 보존한다. 존재하지 않는 날짜는 조용히 보정해 저장하지 않고 거부하며, 저장 성공 안내는 해당 서버 응답 뒤의 첫 사용자 변경·복구부터 숨겨 과거 완료 상태가 다시 나타나지 않게 했다.
- 긴 단일 문단의 `/` 명령 검색은 커서 앞 고정 길이만 확인하고, 노트·게시물 편집 요청은 전체 서버 기준 본문 대신 SHA-256 지문을 보내도록 줄였다. 서버는 실제 조회값과 지문을 대조하고 조건부 갱신·재조회로 동시 저장과 응답 유실 재시도 안전성을 유지한다.
- 대형 문서 입력 중에는 전체 HTML과 초안 서명을 매 키마다 만들지 않고, 입력이 잠시 멈추거나 초안 저장·제출이 필요한 경계에서 최신 문서를 한 번만 직렬화하도록 바꿨다. 마지막 입력은 지연 reader로 초안과 제출값에 그대로 포함한다.
- 제목·날짜·첨부 필드를 포함한 문서 form 전체에서 `Cmd/Ctrl+S`가 각 화면에 표시된 저장 의미를 사용한다. 링크·이미지·YouTube 삽입 panel의 Enter는 바깥 문서를 제출하지 않는다.
- 노트·게시물 편집 성공 응답이 유실된 뒤 같은 저장을 다시 보내도 현재 서버 내용과 일치하면 성공으로 회수하고, 실제 선행 변경만 충돌로 안내한다.
- 초안 복원이 끝나기 전 입력을 잠가 초기 입력 덮어쓰기를 막고, 종료된 Q&A에도 미전송 초안이나 복구본이 있으면 읽기 전용 작성 영역에서 복사·복원할 수 있게 했다.
- 첨부 업로드 오류와 진행률을 접근 가능한 상태로 알리고, 생성 충돌에서 기존 노트를 열 때 직전 학생·워크스페이스 복귀 경로를 보존한다.
- 새 노트·게시물·Q&A 질문·답변은 초안에 생성 작업 식별자를 함께 보존한다. 성공 응답이 유실돼 같은 내용을 다시 보내도 기존 결과를 반환하고, 다른 내용이 먼저 처리된 경우에는 기존 문서를 열거나 별도 문서로 분리하도록 안내한다.
- 동시 탭의 입력을 canonical 초안보다 먼저 내용별 불변 안전본에 저장하고, 충돌·중단 복구본을 직접 복원하거나 삭제할 수 있게 했다.
- 제출 이력을 서명별 30일 tombstone으로 개수 손실 없이 보존하고, 복구본에는 같은 30일 보존·최근 20개 정리와 저장공간 재시도를 적용해 오래 잠든 탭의 초안 재등장을 막는다.
- 저장공간 오류가 계속되면 작성 흐름별 메모리 안전본을 유지하고 이탈 전에 경고한다. 저장소가 회복되면 최신본은 이어 쓰고 나머지는 선택 가능한 복구본으로 승격하며, 제출 완료는 열린 탭에도 전달해 지연된 저장을 중단한다.
- 첨부 업로드·제출 중에는 편집 도구·삽입 panel·저장 단축키·화면 내 링크·취소 이동·panel 닫기를 잠근다. 업로드 URL과 실제 제출 시점 snapshot이 확정된 뒤에만 완료 처리해 첨부나 그 뒤 이어 쓴 내용을 잃지 않게 했다.
- Q&A 스레드·첫 본문과 답변·상태 변경을 D1 batch 또는 로컬 SQLite transaction으로 원자화하고, 격리 D1 실패 주입·경쟁·권한 회귀 테스트를 추가했다.
- 노트와 커뮤니티 게시물을 안정 URL에서 다시 편집하고, 다른 화면의 선행 저장을 감지해 서버 최신본과 현재 초안 중 선택할 수 있게 했다.
- 노트·게시물·Q&A에 사용자·문서별 로컬 초안, 저장 상태와 복원 안내를 추가했다.
- `/` block command, selection format menu와 링크·이미지·YouTube 삽입 panel을 추가했다.
- 포털 section, workspace view, 관리자 학생 선택과 문서 복귀 경로를 URL에 보존한다.
- 저장된 rich text의 hierarchy와 허용된 embed를 공통 renderer로 표시하고, 명시적 태그·속성 허용 목록으로 위험 HTML·UI 위장과 비어 있는 본문을 차단한다.
- 커뮤니티 작성 흐름을 전체 화면 composer로 통합하고 Q&A·노트 작성 후 안정 상세 URL로 이동한다.
- 커뮤니티 채널을 실제 등록 목록으로 검증하고 게시물이 연결된 채널의 삭제를 막아 문서가 목록에서 고립되지 않게 했다.
- owner 정보가 없는 과거 local draft는 계정 간 노출을 막기 위해 자동 이관하지 않는다.
- D1 export, checksum 확인과 격리 restore rehearsal 절차를 배포 가이드에 추가했다.

### 제품 문구와 metadata 정리

#### Changed

- package identity와 페이지 metadata를 Stann Lumo DJ 레슨 포털 제품명에 맞췄다.
- 로그인, 캘린더, 학생 추가, 커뮤니티의 사용자 문구와 작성자·날짜 fallback을 한국어로 통일했다.
- 노트와 카테고리 form의 성공·오류 상태를 공통 semantic token과 live region으로 정리했다.
- 일정 유형, 커리큘럼 완료, 생성 메뉴의 직접 색상 표현을 제품 token으로 교체했다.
- 찾을 수 없는 페이지를 포털의 시각 언어와 실제 복귀 행동에 맞게 다시 구성했다.

#### Accessibility

- 게시물·카테고리 삭제와 오디오 재생 icon control에 맥락이 드러나는 이름을 추가했다.

### 과제·Q&A 상태와 입력 흐름 정리

- 타임라인 피드백 입력을 mobile 1열과 desktop grid로 나누고 모든 입력에 label을 추가했다.

#### Security
